# BMW X5 і X6 з Кореї

Статичний сайт із шортлистом вживаних **BMW X5 (G05)** і **X6 (G06) xDrive30d M Sport**, які підбираються на
[Encar](https://fem.encar.com/) для пригону в Україну. Для кожного авто показана **ціна в Кореї** — рівно та,
що стоїть в оголошенні, у 만원, з довідковим доларовим еквівалентом за курсом 1372 ₩/$ — фото з оголошення,
історія ДТП і — де знято білд-лист BMW за VIN — повна комплектація.

Ціни «під ключ» на сайті немає: мита рахуються від фіксованої митної вартості за роком виготовлення, тобто
однакові для всіх авто одного року, і кандидатів між собою не різнять. Формула лишилась у `tools/customs.py`
— нею `watch.py` тримає критерій «під ключ ≤ $70 000» під час добірки.

**Сайт:** https://volodymyr-babak.github.io/bmw-from-korea/

## Що на сайті

- `index.html` — дві таблиці, X5 і X6: ціна в Кореї, пробіг, VIN, кольори кузова й салону, планки,
  різних ДТП, виплати за ремонт, зміни власника й колонки ключових опцій. Сортування — клік по заголовку,
  фільтри за моделлю, роком, кольорами, кількістю ДТП і наявністю ремонту.
- `car.html?id=<listingId>` — сторінка одного авто: галерея фото з оголошення, заводські рендери за VIN,
  кольори BMW з кодами, історія за корейським реєстром і **повна комплектація за VIN** з українськими
  назвами SA-кодів.

## Структура

```
index.html              головна
car.html                сторінка авто (?id=<listingId>)
assets/css/site.css     стилі, світла й темна теми через CSS-змінні
assets/js/common.js     форматери чисел (만원 → $ за курсом), ключові опції, палітри кольорів, тема
assets/js/options.js    глосарій SA-кодів BMW: українські назви + групування
assets/js/index.js      головна: фільтри, сортування, рендер списку
assets/js/car.js        сторінка авто
data/cars.json          індекс: meta + масив авто (summary для головної)
data/cars/<id>.json     деталь авто: фото, історія, корейська ціна, а де знято білд-лист — і опції
data/sold/<id>.json     архів білд-листів проданих авто (щоб не втратити дефіцитні дані mdecoder)
tools/sync_index.py     підтягує в індекс дані з детальних файлів
```

Дані лежать у JSON і не дублюються в розмітці — сторінки читають їх через `fetch`.

Детальний файл є **в кожного** авто: фото й історія доступні через API Encar одразу.
`decoded: true` в індексі означає інше — що в детальному файлі є `options`, тобто знято
білд-лист BMW за VIN. Фото зберігаються як шляхи Encar (`/carpicture…/…_001.jpg`), а розмір
підставляється в `photoUrl()`; кадр `_001` в Encar — головний ракурс.

## Як додати щойно декодоване авто

1. Дописати в наявний `data/cars/<listingId>.json`: `exterior`/`interior` (`name`, `german`, `code`),
   `keyFeatures`, `options` (усі S-коди з білд-листа mdecoder).
2. Запустити `python3 tools/sync_index.py` — скрипт перенесе VIN, кольори, фото, історію та
   `keyFeatures` в `data/cars.json`, виставить `decoded: true` і перерахує `meta.decodedCount`.
3. Якщо в білд-листі трапився новий S-код, додати його переклад у `assets/js/options.js`.
   Без перекладу код усе одно показується — але в групі «Інше» й англійською.

## Автоматичний моніторинг

`tools/watch.py` запускається щогодини з cron і робить усе сам:

1. **Перевіряє наявні** — деталь кожного лота: `404`, `salesStatus`, приховану ціну.
   Продані прибирає зі списку, живим оновлює ціну й пробіг, а тих, хто виріс
   понад стелю $70 000, теж прибирає.
2. **Шукає нові** — серверні фільтри Encar (рік, пробіг, ціна, `SellType`,
   `FuelType`, `Badge`) звужують видачу до ~170 лотів на дві моделі, це 10 запитів.
   Нові проганяються через історію ДТП і дедуплікацію, відсіяні пишуться
   в `data/watch-state.json`, щоб не перепитувати їх щогодини.
3. **Декодує VIN** — до трьох найперспективніших авто за прохід
   (менша ціна, пробіг, виплати за ремонт і більший рік = вище в черзі).
   Добова квота mdecoder запам'ятовується, наступна спроба — наступного дня.
4. **Публікує** — якщо щось змінилось, комітить `data/` і пушить; сайт
   перезбирається сам.

### Листи

Push у `data/last-change.md` запускає `.github/workflows/notify.yml`, який
створює issue з міткою `encar-watch`. **Issue створює `github-actions[bot]`, а не
власник репо — саме тому лист приходить:** про власні дії GitHub листів не надсилає.

### Керування

```bash
./tools/install-watch-cron.sh          # поставити (щогодини на :17)
crontab -l | grep bmw                  # перевірити
tail -f ~/.cache/bmw-watch.log         # дивитись лог

python3 tools/watch.py --dry-run       # прогін без запису й пушу
python3 tools/watch.py --no-decode     # без mdecoder
python3 tools/watch.py --decode 5      # більше спроб декодування
```

Файли стану: `data/watch-state.json` (журнал відсіяних, квота mdecoder),
`data/watch-log.md` (історія всіх змін), `data/last-change.md` (останній звіт).
Якщо парсер mdecoder не збігся з розміткою, сирий HTML лишається
в `data/mdecoder-raw/<VIN>.html`, а звіт про це прямо каже — дані при цьому
не записуються, щоб у добірку не потрапила вигадка.

## Як перевірити вручну, чи авто ще продається

Це ручна перевірка через API Encar (`https://api.encar.com/v1/readside/vehicle/<listingId>`,
заголовки `User-Agent` + `Referer: https://fem.encar.com/`):

- `HTTP 404` — оголошення знято;
- `advertisement.salesStatus == "CONTRACT"` — продано, підписано контракт;
- `advertisement.price == 9999` — ціну приховано, зазвичай супроводжує продаж;
- `advertisement.price` — актуальна ціна в 만원; саме вона показується на сайті й із неї рахується
  ціна під ключ для критерію добірки.

Продане авто прибирається з `data/cars.json`, а його білд-лист (якщо був) переїжджає
в `data/sold/`, бо добова квота декодера VIN обмежена і ці дані дорогі.

## Локальний запуск

Сторінки використовують ES-модулі й `fetch`, тому їх треба відкривати через сервер, а не з `file://`:

```bash
python3 -m http.server 8000
# http://127.0.0.1:8000/
```

## Формула ціни під ключ (критерій добірки, на сайті не показується)

Мита рахуються від **фіксованої мінімальної митної вартості P за роком виготовлення**, а не від корейської ціни:

| Рік | P (USD) |
|-----|---------|
| 2019 | 25 000 |
| 2020 | 36 000 |
| 2021 | 40 500 |
| 2022 | 43 000 |

```
мито   = 0,10 × P
акциз  = 75 €/л × 3,0 л × вік × 1,1648        вік = 2025 − рік
ПДВ    = 0,20 × (P + мито + акциз)
облік  = 0,05 × P + $124                       сертифікація $79 + реєстрація $45
під ключ = ціна авто + мито + акциз + ПДВ + облік + доставка $3700 + послуги $1000
```

Реалізація — `tools/customs.py` (`landed()`), вартість авто береться з `koreaPriceMan`. Результат
лежить у даних як `priceUSD` і потрібен лише для того, щоб `watch.py` відсіював авто, які не влазять
у стелю $70 000. Сайт це поле не показує.

**Таблиця P звірена для X5.** Для X6 узято ту саму таблицю, тож `priceUSD` для X6 — оцінка
(`priceEstimated: true`, реально +$1000–2000). На відбір це впливає тільки на межі стелі; на те,
що показано на сайті, — ніяк, бо корейська ціна точна.
